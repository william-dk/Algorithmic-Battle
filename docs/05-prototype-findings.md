# 05 · 原型模拟的数据与结论

数据全部来自 `prototype/sim/gen.js`，一个为了出概念图而写的一次性模拟器。规则见 [02-rules-and-algorithms.md](02-rules-and-algorithms.md)。

先说局限：规则是简化版；循环赛每组只有 60 局；第二级的四个示例 AI 非常简单；几场展示用的对局各只跑了一个种子。结论只能当作方向性的参考。

## 结论

### 1. 中盘各方已占格数永远相等

每 tick 各占 1 格，所以比格数没有意义，要比"势力范围"（已占 + 离自己最近的空地）。记分板和曲线都改用了它。

它对终局的预测：

| 对局 | 取样时刻 | 当时的势力占比 | 终局的领地占比 |
|---|---|---|---|
| 2D 四方 | tick 1,277，已填 58% | 15.9 / 32.7 / 31.1 / 19.9 | 18.2 / 30.0 / 31.1 / 20.7 |
| 3D 四方 | tick 2,399，已填 30% | 14.1 / 12.4 / 39.1 / 30.8 | 21.9 / 21.8 / 34.0 / 22.2 |

2D 中盘相当接近。3D 早期只说对了第一名，其余偏差很大。

### 2. 先抢中线筑墙的算法最强

11 种算法两两循环赛，Voronoi 中线优先总胜率 96.8%，对任何对手都不低于 87%。

这推翻了我在最初讨论时的判断。我当时说"BFS 大概率会输给直奔对手筑墙的贪心算法"，实际 BFS 对贪心的胜率是 63%。贪心冲到敌方大本营后只会在周围堆成一团，并没有把对手封住。

我的解读：细长、分叉的生长方式（Prim、随机游走、DFS）能把空间切开，所以胜过抱团生长的算法（BFS、螺旋、A*）。Voronoi 则是有意识地在中线上做这件事。

### 3. 第二级的规则需要调

- 大本营不设额外防御时，"直取大本营"的示例 AI 在 tick 76、165、271 依次灭掉了另外三方。
- 给大本营加 +40 防御后，对局变成：蓝方在 tick 525 被攻陷出局，之后橙、粉两方僵持，一直到 tick 上限 3,000，以 54.8% 对 45.2% 结束，始终没有达到 60% 的占领线。

所以规则参数必须可配置，并靠批量对战来调；胜利条件里的 tick 上限必不可少。

### 4. 性能足够第一阶段不设服务器

2D 展示对局、3D 展示对局、11 张缩略图和 3,300 局循环赛，合计 4.1 秒跑完（Node 24，单线程）。

### 双人测试对局（AI 工坊界面）

64 × 40，可用 2,450 格，种子 77。蓝方是"直取大本营"，橙方是"最小代价"。

- tick 65：双方接壤。
- tick 150（界面取样处）：蓝 209 格，橙 231 格；蓝已夺 23 格，被夺 0 格。
- tick 167：蓝方切断橙方补给，263 格变中立。
- tick 496：蓝方占 71.6%，按占领线获胜。

示例 AI 每 tick 的平均决策耗时在 0.1 到 0.4 毫秒之间，随领地变大而上升（原型的朴素实现，每次全图扫描）。界面上显示的 0.26 毫秒是 tick 150 时的实测值。
